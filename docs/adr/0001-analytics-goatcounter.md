# ADR-0001: 애널리틱스는 GoatCounter를 쓴다 (GA4 아님)

- **상태:** 채택
- **날짜:** 2026-08-04

## 맥락

"예전에 Google Analytics를 붙여둔 것 같다"는 기억에서 출발했으나, 확인 결과 **설치된 적이 없었다**:

- 작업 트리 전체(`site/`, `assets/`, `index.php`, `.htaccess`, 설정 파일)에서 `gtag` / `googletagmanager` / `google-analytics` / `G-` / `UA-` 검색 결과 0건
- `git log --all -S "gtag"`, `-S "googletagmanager"` 모두 0건 — 넣었다 지운 흔적도 없음
- 운영 HTML(`https://massivevoid.com/`, HTTP 200) 응답에도 없음. `<head>`가 로컬 `header.php`와 일치하고 `<script>`는 모바일 메뉴 인라인 하나뿐

GA 콘솔에 속성만 만들어두고 태그 설치를 안 한 상태였을 가능성이 높다.

계측으로 답하고 싶은 질문은 두 개로 좁혀졌다:

1. **어떤 글이 읽히는가** — 다음에 뭘 쓸지 결정에 직접 쓰임
2. **사람이 오긴 오는가**

전환, 이벤트, 퍼널, 잠재고객, 광고 연동은 필요 없다.

## 결정

**GoatCounter**(호스팅, 사이트 코드 `massivevoid`)를 쓴다. GA4는 채택하지 않는다.

스크립트는 **운영 도메인에서만** 출력한다. 사이트 코드를 `site/config/config.massivevoid.com.php`의 `analytics.goatcounter` 옵션에 두고, `site/snippets/header.php`가 그 옵션이 있을 때만 태그를 렌더한다. 이 저장소가 이미 `panel => false`에 쓰고 있는 호스트별 설정 패턴과 동일하다.

방문자 고지는 `about` 페이지 마지막 블록 두 문장으로 갈음한다.

## 근거

**GA4를 버린 이유:**

- 쿠키를 심는다 → 한국 개인정보보호법·EU 방문자 기준 동의 배너 문제가 따라온다. 개인 블로그에 배너를 다는 건 비용 대비 손해
- 애드블로커가 `googletagmanager.com`을 가장 먼저 차단한다. 독자층이 기술 성향(Claude Code, 개발, F1)이라 실측 손실이 크고, 하필 "사람이 오긴 오는가"라는 질문의 답이 체계적으로 축소된다
- "인기 글 순위"를 보려면 `보고서 → 참여도 → 페이지 및 화면`까지 들어가야 한다. 안 보게 된다
- 필요 없다고 정리한 기능들이 GA4의 존재 이유 전부다 — 요구사항 대비 과잉

**GoatCounter를 고른 이유:** 쿠키 없음 → 배너 불필요, 대시보드 첫 화면이 곧 글별 조회수 순위 + 방문자 수, 개인 사이트 무료, 운영 부담 없음. 요구 두 개에 정확히 대응하고 그 이상을 하지 않는다.

**탈락한 대안:**

- **서버 로그 분석(GoAccess)** — Apache `kirby_access.log`가 이미 combined 포맷으로 쌓이고 있어 코드 변경 0으로 가능하다. 그러나 봇 노이즈가 크고 사람/크롤러 구분이 부정확해, 하필 주요 목적인 "글별 순위"가 오염된다. 또 조회하려면 ssh가 필요해 실제로 안 보게 된다
- **Plausible / Umami 등 유료 SaaS** — 방향은 같으나 개인 블로그 규모에 월 비용이 과잉

**운영 전용으로 둔 이유:** 글 17편에 트래픽이 크지 않아, `composer start` 로컬 미리보기가 집계에 섞이면 오염이 신호보다 커질 수 있다. GoatCounter의 `count.js`가 localhost를 자동 제외하는지는 공식 문서에 명시돼 있지 않아, 도구 동작에 기대지 않고 설정 계층에서 분리했다.

## 결과

- 방문자에게 동의 배너를 띄우지 않는다. 이 전제가 깨지는 도구로 바꾸려면 이 ADR을 다시 열어야 한다
- 애드블로커 사용자 일부는 여전히 집계되지 않는다. GoatCounter가 GA보다 덜 차단될 뿐 면역은 아니다 — 숫자는 하한선으로 읽는다
- 검색어별 노출·클릭은 답할 수 없다. 그건 Google Search Console의 영역이고 이번 범위 밖으로 뒀다
- 로컬에서는 태그가 아예 렌더되지 않으므로, 계측 동작 검증은 운영 배포 후에만 가능하다
