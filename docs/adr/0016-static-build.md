# ADR-0016: 운영에는 PHP가 없다 — Kirby는 빌드할 때만 돈다

- **상태:** 채택
- **날짜:** 2026-09-19
- **관련:** [ADR-0003](0003-canonical-host.md), [ADR-0010](0010-asset-cache-busting.md), [ADR-0013](0013-cache-control-tiers.md)

## 맥락

이 사이트는 Lightsail 인스턴스에서 Apache + PHP로 돌았다. 그런데 운영 서버가 실제로 하는 일을 보면 **요청마다 같은 HTML을 다시 만드는 것**뿐이었다.

- 운영 Panel은 꺼져 있다. 글은 로컬에서 쓰고 git으로만 올라간다
- 연락 폼은 HTML 주석 안에 갇힌 채 쓰이지 않고 있었다
- 검색·댓글·로그인처럼 요청 시점에 달라지는 화면이 없다

서버가 하는 일이 없는데 서버 값(월 12,000~13,000원)과 서버 관리(인증서, OS 갱신, `.htaccess` 500의 위험)는 계속 나갔다.

## 결정

**Kirby를 정적 사이트 생성기로 쓴다.** `scripts/build-static.php`가 모든 화면을 한 번씩 그려 `dist/`에 떨구고, GitHub Actions가 그것을 Cloudflare Pages에 올린다.

글 쓰는 방식은 그대로다 — 로컬 Panel에서 쓰고, 커밋하고, `main`에 넣는다. 바뀐 것은 `main` 다음에 오는 것뿐이다.

**플러그인 대신 직접 쓴 스크립트다.** 필요한 일이 넷(화면 그리기, 라우트 떨구기, 미디어 만들기, 자산 옮기기)뿐이고 150줄 남짓이면 끝난다. 아래 "근거"의 함정들은 전부 이 사이트의 다른 결정(정본 주소, 캐시 계층)과 맞물려 있어서, 남의 플러그인 옵션으로 돌려 말하는 것보다 한 파일에 드러나 있는 편이 낫다.

**GitHub Pages가 아니라 Cloudflare Pages다.** GitHub Pages는 응답 헤더를 정할 수 없어 ADR-0013의 캐시 계층을 통째로 잃는다.

## 근거

### 화면은 `blog/index.html`이 아니라 `blog.html`로 떨군다

Cloudflare Pages는 `blog/index.html`을 `/blog/`로 내주고 `/blog`를 거기로 308 넘긴다. 이 사이트의 canonical과 사이트맵은 슬래시 없는 주소다 ([ADR-0003](0003-canonical-host.md)). 그대로 두면 **정본이라고 선언한 주소가 전부 리다이렉트**가 된다. `blog.html`로 떨구면 `/blog`가 200이고 `/blog/`가 넘어온다.

### 미디어는 빌드가 대신 "첫 요청"을 해 준다

Kirby는 이미지를 그릴 때 파일을 만들지 않는다. `media/` 주소만 찍고, 그 주소로 첫 요청이 올 때 원본을 복사하거나 썸네일을 굽는다. 정적 사이트에는 그 요청이 없다. 그래서 스크립트가 그린 HTML에서 `/media/` 주소를 전부 찾아 Kirby 라우터로 한 번씩 부른 뒤, 생긴 파일만 `dist/`로 옮긴다. 부르지 않은 파일은 배포되지 않는다.

### 미디어 해시의 소금을 고정한다

미디어 경로의 해시는 기본적으로 **파일의 절대 경로**를 소금으로 쓴다. 빌드하는 기계가 바뀌면 모든 이미지 주소가 바뀌고, 1년짜리 immutable 캐시가 통째로 버려진다. `content.salt`를 고정해 어디서 빌드해도 같은 주소가 나오게 했다. 이 소금이 지키는 것은 초안 파일의 주소를 추측하지 못하게 하는 것인데, 정적 사이트에는 초안이 배포되지 않는다.

### CI에서 파일 수정시각을 git 이력으로 되돌린다

체크아웃 직후에는 모든 파일의 수정시각이 "지금"이다. 이 사이트에서 수정시각은 세 군데에 쓰인다 — 자산의 `?v=` ([ADR-0010](0010-asset-cache-busting.md)), 미디어 경로 속의 시각, 사이트맵의 `lastmod`. 되돌리지 않으면 **글 한 편을 올릴 때마다 모든 CSS·이미지 주소와 모든 `lastmod`가 바뀐다.** 워크플로가 파일마다 `git log`로 마지막 커밋 시각을 찾아 돌려준다. 그래서 체크아웃은 전체 이력(`fetch-depth: 0`)이다.

`git-restore-mtime` 패키지는 쓰지 않는다. 안에서 부르는 `git whatchanged`를 git 2.51부터 거부하는데, 도구는 경고만 찍고 성공으로 끝난다 — 첫 미리보기 배포가 이렇게 모든 `?v=`와 `lastmod`를 빌드 시각으로 찍어 냈다. 되돌리기가 조용히 실패하면 빌드는 멀쩡히 끝나고 캐시만 매번 버려지므로, 시각을 못 찾으면 멈추는 쪽을 택했다.

### 캐시 계층은 쿼리가 아니라 경로로 가른다

`.htaccess`는 `?v=`가 붙었는지를 보고 계층을 갈랐다. Pages의 `_headers`는 경로만 본다. 그래서 `/assets/css/*`, `/assets/js/*`, `/media/*`는 immutable, 이름이 고정된 파일은 하나씩 적어 하루로 했다. 버전 없는 CSS 주소를 직접 치면 immutable로 나가지만, 그 주소를 내보내는 곳이 없다 — `css()`·`js()`가 언제나 `?v=`를 단다.

`_headers`에서 **규칙이 겹치면 헤더가 덮어써지지 않고 쉼표로 이어붙는다.** `/assets/*`로 기본값을 깔고 `/assets/css/*`로 덮는 방식은 그래서 쓸 수 없다.

HTML은 Pages 기본값(`max-age=0, must-revalidate`)을 그대로 쓴다. 검증자는 붙지 않는다 — Pages는 정적 자산에는 `ETag`를 붙이지만 HTML에는 붙이지 않는다. 그래서 ADR-0013이 "하지 않았다"고 적어 둔 대로, HTML은 여전히 확인할 때마다 전체를 다시 받는다. 전환 직후 실제 도메인에서 확인했다.

### 연락 폼은 남겨 두었다 — 알려진 흠

`about.php`의 폼은 HTML 주석 안에 있지만 **그 안의 PHP는 계속 실행된다** — 그릴 때마다 CSRF 토큰을 굽는다. 정적 빌드에서는 그 토큰이 빌드마다 바뀌어, 내용이 그대로여도 `about.html`만은 매번 다른 파일이 된다. 받을 서버가 없으니 폼이 되살아날 길도 없다. 템플릿의 폼 블록과 `site/controllers/about.php`를 지우면 해결되지만, 이 전환의 범위 밖이라 손대지 않았다.

## 결과

- **월 서버 비용이 0이 된다.** Route 53 호스팅 영역도 Cloudflare DNS로 옮기면서 없어진다.
- **`.htaccess`는 더 이상 운영에 쓰이지 않는다.** 로컬 `composer start`는 PHP 내장 서버라 원래부터 읽지 않았다. 전환이 끝나면 지운다.
- **PR마다 미리보기 주소가 생긴다.** 예전에는 `main`에 넣어야만 실제 환경에서 볼 수 있었다.
- **kirby3-redirects는 정적 사이트에서 동작하지 않는다.** 지금 등록된 리다이렉트가 없어 잃는 것은 없다. 필요해지면 `static/_redirects`에 쓴다.
- **uniform·form·flash 의존성이 남아 있다.** 위의 폼을 지우면 쓰는 곳이 없어진다. 별개 작업으로 남긴다.
- **배포 확인은 여전히 실제 사이트로 한다.** `curl -I`로 보는 네 종류의 헤더(ADR-0013의 표)는 전환 직후 한 번 다시 확인한다.
