# ADR-0012: 본문 열의 폭도 분기점 없이 유동한다

- **상태:** 채택
- **날짜:** 2026-08-18
- **관련:** [ADR-0008](0008-type-scale.md), [ADR-0009](0009-navigation-island.md), [#15](https://github.com/flameware/kirby-blog/issues/15)

## 맥락

열의 폭은 분기점 하나로 두 값 사이를 뛰었다.

```css
.container { box-sizing: border-box; width: 46.7vw; }

@media (max-width: 480px) {
  .container { width: 100%; padding: 0 20px 20px 20px; }
}
```

480px과 481px 사이에서 본문 폭이 **440px → 224.6px으로 절반 아래로 떨어졌다.** 1px 차이로 줄당 글자 수가 26.5자에서 13.6자가 된다. 작은 태블릿과 가로 모드 폰이 데스크톱보다도, 세로 모드 폰보다도 좁은 단으로 글을 읽고 있었다.

[ADR-0008](0008-type-scale.md)이 크기를 유동화하면서 이 구간이 상대적으로 더 나빠졌다. 481px에서 본문이 14px → 16.58px로 커졌는데 폭은 그대로라 줄당 글자 수가 16.7자 → 13.6자로 줄었다. 원인은 폰트가 아니다 — 폭의 분기가 원래 이랬고, 0008은 그것을 드러냈을 뿐이다.

## 결정

**폭도 크기와 같은 원칙을 따른다. 분기점을 없애고 화면 폭에 따라 연속으로 변한다.**

```css
--column: min(100% - 40px, max(46.7vw, 360px + 16.7vw));
```

- `.container`와 `.projects-container footer`가 이 토큰 하나를 쓴다.
- **좌우 여백을 padding에서 폭으로 옮겼다.** 여백이 폭의 일부가 되어 한 값에서 나온다. 모바일 미디어 쿼리에 남은 것은 아래 여백뿐이다.
- 목록 화면의 그리드는 자기 좌우 여백을 자기가 갖는다(`padding: var(--big-gap-mobile) 20px`). 그리드는 화면 전체를 쓰는 요소라 열과 폭을 공유하지 않는다.

세 구간이 min/max만으로 이어진다.

| 구간 | 이기는 항 | 뜻 |
|---|---|---|
| ~480px | `100% - 40px` | 좌우 20px을 뺀 화면 전체 |
| 480~1200px | `360px + 16.7vw` | 두 끝을 잇는 직선 |
| 1200px~ | `46.7vw` | 지금까지의 데스크톱 폭 |

## 근거

**`360px + 16.7vw`는 임의의 값이 아니라 두 끝을 잇는 직선이다.** `100% - 40px`과는 480.2px에서, `46.7vw`와는 정확히 1200px에서 만난다 — `0.467W = 360 + 0.167W`의 해가 `W = 1200`이다. 만나는 점이 곧 구간의 경계라 `min`/`max`가 접합부를 스스로 만든다. 분기점을 손으로 적을 필요가 없고, 그래서 불연속이 생길 자리도 없다.

**끝값 두 개는 기존 화면에서 그대로 가져왔다.** 데스크톱은 `46.7vw`, 좁은 화면은 좌우 20px. 바뀐 것은 그 사이를 잇는 방식뿐이라, 되돌릴 때 볼 곳도 한 줄이다.

**`100vw`가 아니라 `100%`다.** `100vw`는 세로 스크롤바 폭을 포함해서, 스크롤바가 있으면 열이 화면보다 넓어지고 가로 스크롤이 생긴다. 기존 모바일 규칙이 이미 이 이유로 `100%`를 쓰고 있었다.

**미디어 쿼리를 없앤 것이 아니라 폭을 꺼낸 것이다.** 그리드 열 수, 여백, 홈 인사말의 줄바꿈은 여전히 분기가 필요하다. 폭은 연속량이라 분기가 맞지 않았을 뿐이다.

**`figure iframe`의 높이를 비율로 바꿨다.** `height: 26.3vw`는 열이 `46.7vw`로 고정이던 시절의 16:9였다. 열이 화면 폭을 따라 변하면 그 값은 더 이상 비율이 아니다 — 768px에서 2.4:1로 납작해졌을 것이다. `aspect-ratio: 16 / 9`는 폭이 무엇이든 비율을 지키므로, 모바일 전용 `56.25vw` 규칙도 함께 사라졌다.

**빈 미디어 쿼리 24개(`320px`/`375px`/`414px`/`430px`/`481–768px`)를 지웠다.** ADR-0008이 "크기 변경과 청소가 뒤섞이면 되짚기 어렵다"며 남겨둔 것들이다. 이번 변경은 바로 그 `481–768px` 구간을 다루므로, 여기서 지우는 것이 오히려 맥락에 맞는다.

## 결과

- **데스크톱(≥1200px)과 세로 모드 폰(≤480px)의 본문 폭은 픽셀 단위로 그대로다.** 바뀐 것은 그 사이뿐이다.

  | 뷰포트 | 이전 | 이후 | 줄당 글자 수 (이전 → 이후) |
  |---|---|---|---|
  | 480px | 440.0 | 440.0 | 26.5 → 26.5 |
  | **481px** | **224.6** | **440.3** | **13.6 → 26.6** |
  | 768px | 358.6 | 488.3 | 20.0 → 27.2 |
  | 1000px | 467.0 | 527.0 | 24.5 → 27.7 |
  | 1200px | 560.4 | 560.4 | 28.0 → 28.0 |

  네 화면(홈·목록·프로젝트·소개) 모두에서 브라우저로 측정했다. 480/481 경계의 불연속은 0.3px이고, 그것은 직선이 480.2px에서 만나기 때문이다.

- **줄당 글자 수가 폭 전체에서 단조 증가한다.** 320px의 17.5자에서 1200px의 28.0자까지, 중간에 꺼지는 구간이 없다.
- **내비게이션은 어느 폭에서도 접히지 않는다.** 높이가 320~1600px 전 구간에서 54px로 일정하다. 열 바깥에 있는 island이라 애초에 열 폭의 영향을 받지 않는다([ADR-0009](0009-navigation-island.md)).
- **새 폭이 필요하면 분기가 아니라 끝값을 고친다.** 화면 폭별 분기를 새로 만들 이유는 크기와 마찬가지로 폭에도 없다.
- `CONTEXT.md`는 갱신하지 않았다. 여기서 정한 것은 전부 구현이고, 도메인 용어(본문·목록·내비게이션)는 이미 정의돼 있다.
