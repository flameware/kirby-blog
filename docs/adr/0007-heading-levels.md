# ADR-0007: 소제목은 h2에서 시작하고, 크기는 태그 이름이 아니라 역할을 따른다

- **상태:** 채택
- **날짜:** 2026-08-17
- **관련:** [#7](https://github.com/flameware/kirby-blog/issues/7), [ADR-0004](0004-title-field.md)

## 맥락

ADR-0004로 제목이 `<h1 class="post-title">`이 되면서, 본문 소제목의 레벨이 어긋난 채 남았다. 소제목은 markdown 블록 안에 `###`로 쓰여 있어 `<h3>`로 나왔고, 문서 아웃라인이 **h1 → h3로 h2를 건너뛰었다**.

#7이 적어둔 현황(`###` 65곳 / 18편, "heading 블록 0개")은 **블로그 글만 센 것**이었다. 실제 조사 결과는 다르다.

| 곳 | 헤딩 | 비고 |
|---|---|---|
| 글 18편 | `###` 73, `####` 12 | |
| 프로젝트 23편 | 각 1개 (`###` 22, `##` 1) | **본문 첫 줄이 제목을 그대로 되풀이** |
| about | `###` 1, `####` 4 | |
| 합계 | **113곳** | |

프로젝트에서 나온 것이 ADR-0004의 사각지대다. ADR-0004는 heading **블록**만 제거했는데, 프로젝트의 제목 되풀이는 markdown 블록 **안의 텍스트**여서 그물에 걸리지 않았다. 그래서 프로젝트 23편 전부가 `project.php`의 `<h1>`과 본문 헤딩으로 **제목을 두 번 보여주고 있었다**.

CSS 쪽에도 걸림돌이 있었다. `###`를 `##`로 올리면 `--text-h2`(1.802rem)가 `.post-title`이 쓰는 크기와 정확히 같아, 제목과 소제목이 시각적으로 구별되지 않는다. 마크업만 고치면 화면이 나빠진다.

## 결정

**본문 소제목은 h2에서 시작한다. 크기는 태그 이름이 아니라 역할이 정한다.**

- 글·about 90곳의 소제목을 한 단계씩 올렸다 (`###` → `##`, `####` → `###`).
- 프로젝트 23편의 되풀이된 제목은 본문에서 **제거**했다. ADR-0004의 규칙("제목은 `title` 필드 하나, 본문에 두지 않는다")을 놓친 곳에 마저 적용한 것이다.
- 값이 어긋난 4편은 ADR-0004와 같은 근거로 **화면에 보이던 헤딩 값을 정본**으로 삼아 `title` 필드를 덮었다.

  | 슬러그 | 이전 `title` | 이후 |
  |---|---|---|
  | `black-and-whites` | Black and Whites | Black, White, Sine & Cosine |
  | `fibonacci` | Fibonacci | Fibonacci Sequence |
  | `braille-for-us` | Braille for Us | Braille For Us |
  | `circles-with-random-feelings` | Circles with Random Feelings | Circles with random feelings |

  URL은 폴더명이라 그대로다.
- `index.css`의 `h2`·`h3` 규칙을 한 칸씩 내려 다시 붙였다. `h2`는 이전 `h3`의 크기·여백(`--text-h3`, 위쪽 `--big-gap`)을, `h3`는 이전 `h4`의 모습(본문 크기 + 굵기)을 갖는다.
- `.blog-heading`(heading 블록)의 개별 `padding`을 지워 `h2` 규칙 하나만 쓰게 했다.

## 근거

**화면은 픽셀 단위로 그대로 둔다.** 이 작업은 아웃라인을 고치는 일이지 디자인을 바꾸는 일이 아니다. 되돌릴 일이 생겼을 때 "마크업 때문인지 디자인 때문인지"를 나눠 볼 수 있어야 한다. 실제로 마이그레이션 전후의 계산된 스타일이 데스크톱·모바일 모두에서 완전히 같음을 확인했다 — 태그 이름만 바뀌었다.

```
이전  H3 32.04px / lh 44.856 / padding-top 80    →  이후  H2 32.04px / lh 44.856 / padding-top 80
이전  H4 20px    / lh 36     / margin 26.6       →  이후  H3 20px    / lh 36     / margin 26.6
```

**토큰 값(`--text-h2` 등)은 건드리지 않았다.** `--text-h2`를 소제목용으로 낮추는 방법도 있었지만, 그 토큰을 `.post-title`이 쓰고 있어서 제목까지 같이 줄어든다. 토큰은 타입 스케일의 눈금이고, 어느 눈금을 어느 태그에 붙일지는 규칙이 정하는 편이 낫다. 그래서 눈금은 두고 매핑만 옮겼다.

**`--text-h2`와 `--text-h1`은 이제 각각 `.post-title`과 `default.php`의 `h1`만 쓴다.** 스케일에 빈 칸이 생긴 셈이지만, 제목이 커지는 방향으로 디자인을 바꾸기로 하면 다시 쓸 눈금이다. 지워서 얻을 것이 없다.

**about은 이번에 손대지 않았다.** `about.php`는 제목을 렌더하지 않아 `<h1>`이 아예 없고, 본문이 인사말로 시작한다. 레벨만 올려 h2 → h3로 정리했지만 아웃라인은 여전히 h1이 없다. 홈·목록 화면도 `<h1>`이 없기는 마찬가지라, "제목 없는 화면"은 한 번에 같이 볼 문제다. → [#11](https://github.com/flameware/kirby-blog/issues/11)

**홈의 소개 문장은 크기를 붙들었다.** `home.php`가 인사말을 `<h3>`로 감싸고 있어서, `h3` 규칙이 본문 크기로 내려가면 같이 줄어든다. `home.css`에서 `.home-intro h3`의 크기를 이전 값으로 고정했다. 이 문장은 애초에 소제목이 아니므로 문단으로 바꾸는 게 맞지만, 그건 위의 아웃라인 정리와 함께 볼 일이다.

## 결과

- **글을 쓸 때 본문 소제목은 `##`부터 시작한다.** `#`은 제목의 자리이므로 본문에 쓰지 않는다. 패널의 heading 블록도 `<h2>`로 나오므로 markdown `##`과 같은 것을 뜻한다.
- 소제목의 소제목이 필요하면 `###`이다. 크기는 본문과 같고 굵기로만 구분되므로, 깊이가 더 필요하다면 글을 나누는 편이 낫다.
- 프로젝트 4편의 제목이 바뀌었다. `<title>`·공유 카드·목록·이웃 글 링크가 모두 바뀐 값을 쓴다. URL은 그대로다.
- 프로젝트 상세 화면에서 제목 되풀이가 사라졌다.
