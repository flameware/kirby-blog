# ADR-0014: 형광펜은 밑줄이 아니라 글자를 감싸는 인라인 상자의 배경이다

- **상태:** 채택
- **날짜:** 2026-08-20
- **관련:** [ADR-0007](0007-heading-levels.md), [ADR-0009](0009-navigation-island.md)

## 맥락

링크 hover와 내비게이션의 현재 화면 표시는 노란 형광펜이다. 구현은 **1em짜리 두꺼운 밑줄을 글자 뒤로 밀어 넣은 것**이었다.

```css
a:hover {
  text-decoration: underline;
  text-decoration-thickness: 1em;
  text-underline-offset: -1em;
}
```

영리하고, 오래 잘 작동했다. 특히 [ADR-0009](0009-navigation-island.md)가 내비게이션 링크의 클릭 영역을 44×44px로 키울 때 이 성질이 결정을 가볍게 만들었다 — 밑줄은 글자에 붙는 장식이라 링크 상자가 아무리 커져도 형광펜 모양이 변하지 않았다. 그 문서는 이것을 근거로 "활성 표시로 알약 배경을 골랐다면 이 결정이 훨씬 무거웠을 것"이라고 적었다.

그런데 밑줄로 그은 형광펜은 **글자 상자에 정확히 갇혀 있다.** 글자 왼쪽 끝에서 시작해 오른쪽 끝에서 끝나고, 언제나 기준선과 완벽하게 평행하다. 실제 형광펜은 그렇지 않다. 획이 낱말보다 넓게 지나가고 수평에서 조금 어긋난다. 그 차이가 내비게이션에서 "글자에 딱 맞아 답답하다"로 읽혔다.

`text-decoration`으로는 둘 다 불가능하다. 좌우로 넘칠 방법이 없고, 회전할 방법도 없다.

## 결정

**형광펜을 배경으로 바꾼다. 그리고 그 배경이 붙을 자리로 "글자를 감싸는 인라인 상자"를 마크업에 명시한다.**

```css
a:hover:not(:has(span, img)),
a:hover span,
.mainnav-links a[aria-current="page"] span {
    padding-inline: 0.35em;
    margin-inline: -0.35em;

    background-image: linear-gradient(179deg,
        transparent 15.6%,
        var(--color-highlight) 15.6%,
        var(--color-highlight) 84.4%,
        transparent 84.4%);
    background-size: 100% 1.6em;
    background-position: 0 50%;
    background-repeat: no-repeat;
    box-decoration-break: clone;
}
```

세 가지가 맞물려 있다.

**삐져나옴은 `padding-inline`과 같은 크기의 음수 `margin-inline`이다.** 배경은 패딩 상자까지 칠해지므로 마커가 좌우로 `0.35em`씩 넓어지고, 음수 마진이 그만큼을 되돌려 **레이아웃은 한 픽셀도 밀리지 않는다.** 단위가 `px`이 아니라 `em`인 것은 형광펜이 글자에 붙는 장식이기 때문이다 — 글자가 커지면 획도 굵어진다. [ADR-0008](0008-type-scale.md)이 크기에, [ADR-0012](0012-fluid-column-width.md)가 폭에 세운 원칙과 같다.

**기울기는 `transform`이 아니라 그라디언트의 각도로 만든다.** `transform`은 인라인 요소에 듣지 않아 절대배치가 필요하고, 그러면 줄바꿈되는 본문 링크에서 마커 하나가 두 줄에 비스듬히 걸친다. 그라디언트는 인라인 상자에 그대로 걸리고 `box-decoration-break: clone`이 줄마다 다시 그어 준다. 띠는 `1.6em` 타일 안의 가운데 `1.1em`이다 — 타일에 여유가 없으면 기울일 자리가 없다.

**마커가 붙을 상자를 마크업에서 만든다.** flex 링크(내비게이션·목록)의 글자는 익명 인라인 상자라 배경을 걸 대상이 아예 없고, 링크 자체에 걸면 44px 클릭 영역이 통째로 칠해진다. 그래서 글자를 `<span>`으로 감싼다.

```php
<li><a href="..." aria-current="page"><span>Blog</span></a></li>   <!-- 내비게이션 -->
<a href="..."><span><?= $blogpost->title()->esc() ?></span></a>     <!-- 목록 -->
<figcaption><span><?= $project->title() ?></span></figcaption>      <!-- 프로젝트 -->
```

**클릭 영역을 갖는 상자와 마커를 갖는 상자를 분리한다** — 이것이 이 결정의 한 문장이다. 목록 링크에 있던 `<a><p>제목</p></a>`의 `<p>`는 `<span>`으로 바꿨다. 블록인 `<p>`에 마커를 걸면 열 전체 폭에 노란 띠가 그어지고, 애초에 `<a>` 안의 `<p>`는 잘못 놓인 마크업이었다.

`:has(span, img)`가 세 경우를 하나의 선택자로 가른다. span이 있으면 span이 마커 상자, 없으면 링크 자체가 마커 상자(Kirby가 만드는 본문 인라인 링크), 이미지만 감싼 링크는 칠할 글자가 없다.

## 결과

**[ADR-0009](0009-navigation-island.md)의 근거 하나가 무효가 되었다.** 형광펜은 더 이상 "글자에 붙어 클릭 영역과 무관한" 장식이 아니다. 44px 클릭 영역은 그대로 살아남았지만, 그것은 성질 덕분이 아니라 `<span>`을 넣어 **지켜낸** 것이다. 0009는 그때의 판단 기록이므로 고치지 않고 이 문서를 상호참조로 걸었다.

**hover와 현재 화면 표시는 여전히 같은 모양이다.** 0009가 알고 받아들인 그 결정을 그대로 유지했고, 이번에 두 곳에 복제돼 있던 선언을 **하나로 합쳤다.** 값이 사는 곳이 하나이므로 `--marker-bleed` 같은 토큰은 만들지 않았다 — 토큰은 두 곳 이상에서 쓰일 때 값을 한다.

**기울기가 링크 폭에 비례한다.** 색 경계만 비스듬한 방식이라 기울기의 절대량은 `폭 × tan(1°)`다. 내비게이션 링크(약 56px)에서는 1px 미만이라 사실상 보이지 않고, 목록 제목(약 340px)에서는 6px로 또렷하다. 내비게이션에서 답답함을 푸는 일은 기울기가 아니라 **삐져나옴이 한다.** 각도를 키워 내비게이션에서도 보이게 하려면 긴 링크에서 띠가 타일 밖으로 잘린다 — 가장 넓은 링크가 각도의 상한을 정한다. 알고 받아들였다.

**전환 효과는 넣지 않았다.** 이 사이트에는 트랜지션이 하나도 없다. 하나를 들이면 "왜 여기만?"이 생기고 그다음 요소마다 같은 질문이 붙는다. 그을 맛은 모양에서 나오게 하고 시간은 쓰지 않는다.

**`:nth-child`로 링크마다 각도를 달리하는 변주는 기각했다.** 손맛은 한 단 올라가지만 내비게이션에서만 성립하고(본문 인라인 링크에는 기준이 없다), 결국 "여기서만 통하는 두 번째 어휘"가 된다 — 0009가 같은 이유로 기각한 방향이다.

**`.projects a:hover`에 복제돼 있던 밑줄 선언도 지웠다.** 전역 규칙 하나가 사이트의 모든 링크를 담당한다.
