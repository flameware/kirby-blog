# ADR-0002: 이전/다음 내비게이션의 이웃은 목록 순서를 따른다

- **상태:** 채택
- **날짜:** 2026-08-10
- **관련:** [#1](https://github.com/flameware/kirby-blog/issues/1)

## 맥락

블로그 글과 프로젝트 상세 하단에 `< 이전` / `다음 >` 링크를 붙이려면, "이웃"이 무엇인지부터 정의해야 했다. 이 저장소에는 후보 기준이 두 개 있다:

- **패널 수동 정렬(폴더 num).** `blog.yml` / `projects.yml` 어디에도 `sortBy`가 없어, 두 섹션 모두 num이 정렬 기준이고 `blog.php` / `projects.php`의 화면 나열 순서가 곧 num 순서다.
- **`Date` 필드.** 두 블루프린트 모두 가지고 있다.

두 기준이 갈리는 지점이 실제로 존재한다:

- **블로그**는 num 순서와 날짜 내림차순이 현재 17편 전부 일치한다(num 1 = 2026-07-19, num 17 = 2025-08-07).
- **프로젝트**는 전혀 일치하지 않는다. num 1 = 2017-09-07, num 17 = 2021-04-06, num 21 = 2021-04-28. 즉 프로젝트의 num은 시간이 아니라 **직접 큐레이션한 진열 순서**다.

여기에 방향 문제가 겹친다. 두 목록 모두 "위가 우선"이지만, 블로그에서 위는 최신 글이다. "목록에서 앞 = 이전"으로 두면 블로그에서 `< 이전`이 **더 최신 글**을 가리키게 된다.

## 결정

**이웃은 부모의 listed 자식 목록 순서(num)를 따른다. 블로그·프로젝트 공통이며 분기하지 않는다.**

- `< 이전` = 목록에서 **아래쪽** 항목 → Kirby `$page->nextListed()`
- `다음 >` = 목록에서 **위쪽** 항목 → Kirby `$page->prevListed()`

**목록에 없는(unlisted) 페이지에서는 내비게이션을 통째로 숨긴다.** 스니펫 첫 줄의 `$page->isListed()` 가드가 이를 담당한다.

구현은 `site/snippets/postnav.php` 하나이며 `blogpost.php`와 `project.php`가 공유한다. 스타일은 두 템플릿이 공유하므로 `assets/css/index.css`에 둔다 — 템플릿별 CSS는 `css("@auto")`로 한쪽만 로드되기 때문이다.

## 근거

**`Date`가 아니라 num을 고른 이유:** 이전/다음은 "방금 본 목록의 앞뒤"라는 기대를 배신하면 안 된다. 프로젝트에서 날짜 정렬을 쓰면 화면 진열 순서와 이동 순서가 즉시 어긋난다. num을 기준으로 두면 내비게이션이 목록과 항상 일치한다는 보장이 생기고, 블로그에서는 num이 이미 날짜 내림차순이라 날짜 기준과 결과가 같다.

**방향을 `이전 = 목록 아래`로 통일한 이유:** 블로그에서 `< 이전`이 더 오래된 글이어야 한다는 것이 이 기능 요청의 핵심 의도였다. 프로젝트에서도 "이전 = 진열 순서상 더 뒤" 로 읽히므로, 규칙 하나로 두 섹션을 덮을 수 있다. 섹션마다 방향을 뒤집으려면 스니펫에 방향 인자가 필요해지는데, 그 복잡도를 살 만큼의 이득이 없다.

**unlisted를 숨기는 이유:** `3d-typography`, `line-works`는 URL로는 열리지만 목록에 없다. Kirby의 기본 형제 컬렉션은 unlisted 페이지를 맨 뒤에 포함하므로, 가드가 없으면 `prevListed()`가 마지막 listed 프로젝트를 반환해 **들어갈 수는 있으나 되돌아올 수는 없는** 비대칭 경로가 생긴다. 순서상 위치가 정의되지 않은 페이지에는 순서 기반 UI를 붙이지 않는다.

**대상 글 제목을 화면에 노출하지 않은 이유:** 라벨 두 단어로 좌우 배치가 모바일까지 그대로 유지된다. 제목은 `title` / `aria-label` 로만 실어 접근성과 툴팁을 챙긴다.

## 결과

- **새 글을 발행하면 패널에서 맨 위로 끌어올려야 한다.** Kirby는 수동 정렬 섹션에서 새 페이지의 num을 맨 뒤에 붙인다. 잊으면 목록과 내비게이션이 함께 어긋난다(둘은 여전히 서로 일치한다).
- 프로젝트를 나중에 날짜순으로 재정렬하고 싶어지면, 이 ADR이 아니라 `projects.yml`에 `sortBy`를 넣어 **목록 자체**를 바꿔야 한다. 내비게이션은 자동으로 따라온다.
- 블로그 목록을 `Date` 정렬로 바꾸는 날에는 이 결정을 다시 열 필요가 없다 — 규칙이 "목록 순서를 따른다"이므로 그대로 성립한다.
