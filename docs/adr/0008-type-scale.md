# ADR-0008: 크기는 유동 단위 하나에서 나오고, 토큰 이름은 역할을 가리킨다

- **상태:** 채택
- **날짜:** 2026-08-17
- **관련:** [ADR-0007](0007-heading-levels.md), [#11](https://github.com/flameware/kirby-blog/issues/11)

## 맥락

모바일에서 글자가 전체적으로 작다는 문제 제기에서 출발했다. 조사해 보니 원인은 개별 토큰이 아니라 **사다리가 딛고 선 바닥** 하나였다.

```css
html { font-size: clamp(14px, 2vw, 20px); }
```

모든 토큰이 `rem`이라 루트가 세트 전체를 통째로 곱한다. `2vw`가 14px이 되는 지점은 뷰포트 **700px** — 즉 700px 이하의 모든 화면에서 루트는 14px에 고정되고, 1000px 이상에서 20px이다. **모바일은 데스크톱의 일괄 0.7배**였다.

문제는 세 겹이었다.

1. **본문 14px.** 세리프 한글 본문의 통상 하한(15~17px) 아래다.
2. **모바일 스케일의 비율까지 눌려 있었다.** 데스크톱은 1.125 등비(소제목/본문 = 1.60배)인데, `--text-*-mobile` 3종은 1.067 등비(1.30배)였다. 작아진 데다 위계까지 평평해서 체감이 두 배로 왔다.
3. **481~700px가 사각지대였다.** 미디어 쿼리 분기는 480px인데 루트 바닥은 700px에서 이미 닿는다. 그 사이 폭은 **본문 14px에 소제목 32px**이라는 조합이 나왔다.

한편 rem 값 자체는 이미 옳았다. `0.79 = 1.125⁻²`, `0.889 = 1.125⁻¹`, `1.602 = 1.125⁴`, `1.802 = 1.125⁵` — 1rem 기준의 정확한 1.125 등비 사다리다. **사다리는 맞았고 바닥이 틀렸다.**

토큰 이름에도 문제가 있었다. ADR-0007 이후 `h2` 태그(소제목)가 `--text-h3`를 쓰고 `--text-h2`는 `.post-title`(제목)만 쓰게 되면서, 이름이 실제 쓰임과 어긋났다. 0007이 "빈 칸이 생겼지만 지워서 얻을 게 없다"고 남겨둔 것이 이 어긋남이다.

## 결정

**크기는 유동 단위 하나에서 나온다. 분기점도, 모바일 전용 토큰도 두지 않는다.**

```css
--fluid: clamp(1rem, 0.893rem + 0.476vw, 1.25rem);  /* 360px에서 16px → 1200px에서 20px */

--text-tag:     calc(var(--fluid) * 0.79);    /* 12.6px → 15.8px */
--text-meta:    calc(var(--fluid) * 0.889);   /* 14.2px → 17.8px */
--text-body:    var(--fluid);                 /* 16.0px → 20.0px */
--text-subhead: calc(var(--fluid) * 1.602);   /* 25.6px → 32.0px */
--text-title:   calc(var(--fluid) * 1.802);   /* 28.8px → 36.0px */
```

- `html`의 `font-size` 지정을 **제거**했다.
- `--text-*-mobile` 3종, 미디어 쿼리 안의 `h1`/`h2`/`h3` 크기 규칙, `.home-intro h3`의 모바일 크기 지정을 모두 지웠다. 모바일 미디어 쿼리에는 여백 조정만 남았다.
- **토큰 이름을 태그가 아니라 역할로 바꿨다.** `CONTEXT.md`가 이미 정의한 용어(태그·작성일·본문·소제목·제목)를 그대로 쓴다.
- `--text-nav`를 `--text-body`로 흡수했다. 값이 본문과 같은데 이름만 다른 토큰은 지키지 않는 의도를 코드에 남겨둔 상태였다.
- **사다리 최상단(`--text-h1`)을 지웠다.** 유일한 사용처가 404 화면이었고(`default.php`를 쓰는 페이지는 `content/error` 하나뿐이다), 404 제목이 글 제목보다 커야 할 이유가 없다.
- 데스크톱은 건드리지 않았다. 유동 구간의 위쪽 끝을 기존 값에 맞췄다.

## 근거

**`clamp(a,b,c) × N = clamp(aN,bN,cN)`이라서 유동 단위 하나로 충분하다.** 토큰마다 `clamp`를 쓸 필요가 없고, 배수는 순수한 눈금으로 남는다. ADR-0007이 세운 "토큰은 타입 스케일의 눈금이고, 어느 눈금을 어디에 붙일지는 규칙이 정한다"가 그대로 유지된다 — 눈금이 고정값에서 범위로 바뀌었을 뿐이다. 되돌리거나 조정할 때 건드릴 곳이 한 줄이라는 것도 이 구조의 값이다.

**분기점을 없앤 것이 481~700px 사각지대를 특별 취급 없이 해결한다.** 기기 목록을 늘려 대응하는 대신, 크기가 폭을 따라 연속적으로 변하면 그런 목록 자체가 필요 없어진다.

**독자의 브라우저 글자 크기 설정이 처음으로 존중된다.** 기존 `clamp(14px, 2vw, 20px)`은 px 고정이라 설정을 완전히 무시했다. 부수 효과가 아니라 이 구조를 택한 이유 중 하나다.

**모바일 헤딩을 따로 깎지 않았다.** 아래쪽 끝에서만 헤딩을 한 칸 낮추는 안(소제목 22.8px)도 있었지만, 그러면 "배수는 눈금이다"에 예외가 하나 생기고 그 예외는 코드에 남아 다음 사람에게 왜인지를 묻게 만든다. 화면을 보고 과하다 싶으면 배수만 바꾸면 되므로 되돌리기가 싸다.

**줄 길이가 짧아지는 것을 대가로 지불했다.** 360px 화면에서 본문 한 줄이 22.9자 → 20.0자가 된다. 좌우 여백(20px)을 줄여 벌충하는 안을 검토했지만, 양쪽 합쳐 8px은 **줄당 0.5자**밖에 되지 않아 지렛대가 못 된다. 대신 이미지가 화면 가장자리에 더 붙는 부작용만 남는다. 폰에서 줄이 짧은 것은 매체의 성질이고 14px은 결함이라고 판단해, 여백과 `line-height: 1.8`은 그대로 두었다.

**빈 미디어 쿼리 24개(`320px`/`375px`/`414px`/`430px`/`481–768px`)는 남겨두었다.** 이번 변경과 무관하고, 같이 지우면 diff에서 크기 변경과 청소가 뒤섞여 되짚기 어려워진다.

## 결과

- **데스크톱(≥1200px)은 픽셀 단위로 그대로다.** 본문 20 / 제목 36.04 / 소제목 32.04 / 작성일 17.78 / 태그 15.8 — 변경 전과 같음을 브라우저에서 확인했다.

  | 뷰포트 | 본문 | 소제목 | 제목 | 작성일 | 태그 |
  |---|---|---|---|---|---|
  | 360px | 16.00 | 25.63 | 28.83 | 14.23 | 12.64 |
  | 390px | 16.14 | 25.86 | 29.09 | 14.35 | 12.75 |
  | 700px | 17.62 | 28.23 | 31.75 | 15.66 | 13.92 |
  | 1200px | 20.00 | 32.04 | 36.04 | 17.78 | 15.80 |

- 모바일 소제목이 18.1 → 25.6px, 제목이 19.4 → 28.8px로 커졌다. 본문(14 → 16px)보다 크게 뛰는 이유는 기존 모바일 헤딩이 **바닥과 비율 양쪽으로 눌려 있었기** 때문이다.
- **홈 인사말의 `<br />`을 좁은 화면에서 무력화했다.** 고정 크기를 전제하고 손으로 박아둔 줄바꿈이라, 크기가 변하니 각 줄이 화면을 넘겨 다시 접히면서 너덜너덜해졌다. `.home-intro br { display: none }` 한 줄로 막았다. 이 문장을 `<p>`로 바꾸는 것은 여전히 홈의 아웃라인 정리와 함께 볼 일이다 → [#11](https://github.com/flameware/kirby-blog/issues/11)
- **글을 쓰거나 CSS를 고칠 때 크기는 다섯 토큰 중에서 고른다.** 새 크기가 필요하면 토큰을 추가하는 게 아니라 배수를 정해 눈금에 얹는다. 화면 폭별 분기를 새로 만들 이유는 없다.
- `CONTEXT.md`는 갱신하지 않았다. 여기서 정한 것은 전부 구현(유동 단위·뷰포트 구간·배수)이고, 도메인 용어는 이미 정의돼 있다. 이번 작업은 오히려 CSS를 그 용어 쪽으로 끌어온 것이다.
