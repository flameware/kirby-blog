# ADR-0019: 내비게이션은 본문 열에 맞춘 텍스트 줄이고, 스크롤하면 위에 붙는다

- **상태:** 채택 — [ADR-0009](0009-navigation-island.md)를 대체한다
- **날짜:** 2026-09-29
- **관련:** [ADR-0008](0008-type-scale.md), [ADR-0012](0012-fluid-column-width.md), [ADR-0014](0014-highlight-marker.md), [ADR-0015](0015-own-javascript.md)

## 맥락

ADR-0009의 island(내용만큼만 차지하고 화면 중앙에 떠 있는 둥근 상자)는 쓰다 보니 이 블로그에 어울리지 않았다. 진단은 셋이었다.

- **테두리 상자가 앱 UI처럼 읽힌다.** island은 아바타·테마 토글까지 담은 투자일지에서 온 형태다. 링크 셋짜리 글 중심 사이트에서 둥근 테두리는 필요 이상으로 "컨트롤"이었다.
- **본문 열과 따로 논다.** 폭이 열(46.7vw)과 무관해서, 좌우 끝이 본문의 어느 선에도 맞지 않았다.
- **무겁다.** 모든 화면 꼭대기에 상자가 있어 첫 시선을 가져갔다.

브랜드가 화면 중앙에 오는 것은 문제로 꼽지 않았다.

세 방향을 실제 화면에서 전환해 보며 비교했다 — A 열 정렬 텍스트 줄, B 전체폭 바(아래 선), C 마스트헤드(브랜드 가운데, 링크 아래 한 줄). sticky는 형태와 따로 켜는 스위치였고, 켰을 때의 세로 여백(0/8/12px)과 붙었을 때의 선(없음/열 폭/전체폭)도 골랐다. 시안 코드는 `prototype/nav-variants` 브랜치에 남아 있다.

## 결정

**A + sticky + 세로 여백 12px + 붙었을 때만 전체폭 선.**

- **테두리·둥근 모서리가 없다.** 브랜드의 왼쪽 끝과 마지막 링크 글자의 오른쪽 끝이 본문 열(`--column`)의 두 가장자리에 맞는다.
- **요소는 화면 전폭이고, 내용은 좌우 패딩으로 열 안에 가둔다.** 여전히 `<body>`의 직계 자식이다.
- **`position: sticky; top: 0`.** 흐름 안에서 시작해 위에 닿으면 붙는다. 붙은 높이는 69px이다(44px 링크 + 위아래 12px + 선 1px).
- **선은 붙었을 때만 보인다.** 테두리는 늘 있고 색만 투명에서 `--color-secondary`로 바뀐다.
- **붙었는지는 `assets/js/nav.js`가 판정해** `.mainnav`에 `data-stuck`을 붙인다.
- **모바일 분기는 여전히 없다.** 폭 예산은 유동값의 하한으로 맞춘다.
- 그대로 둔 것: 브랜드 `--text-body` / 링크 대문자 `--text-tag`, 44px 클릭 영역(하한), `aria-current` 형광펜, 그림자 없음.

## 근거

**전폭 요소에 패딩으로 열을 만든다.** 열 폭짜리 요소를 sticky로 만들면 본문이 좌우 여백으로 비쳐 지나가고, 선도 열 폭에서 끊긴다. 시안은 `box-shadow: 0 0 0 100vmax` + `clip-path`로 배경을 화면 끝까지 늘렸는데, 그림자 어휘를 배경 칠하기에 빌려 쓰는 꼼수다. 전폭 요소에 `padding-inline: calc((100% - var(--column)) / 2)`를 주면 배경과 테두리가 저절로 화면 끝까지 간다. 패딩의 `100%`는 containing block인 `<body>`의 폭이라 `--column`의 `100%`와 같은 값으로 풀린다.

**세로 패딩만큼 위 여백에서 뺀다.** `margin-top: calc(5.6vw - 12px)`, 모바일은 `20px - 12px`. 스크롤 전 글자의 자리는 ADR-0009 때와 같다 — 열이 쓰던 세로 리듬을 그대로 물려받는다. 붙을 때만 여백을 바꾸면 요소 높이가 변해 본문이 튄다.

**선은 붙었을 때만.** 흐름 안에 있을 때 선이 있으면 첫 화면이 사실상 B(전체폭 바)가 되고, 붙은 뒤에 선이 없으면 본문이 흰 띠 밑으로 경계 없이 잘려 들어간다. 테두리를 늘 두고 색만 바꾸는 것은 붙는 순간 높이가 1px 변하지 않게 하려는 것이다.

**판정은 JS가 한다.** CSS만으로는 sticky가 붙었는지 알 수 없다. `animation-timeline: scroll()`로 "위 여백만큼 스크롤하면 선이 나타나게" 하는 방법도 있었지만, 스크롤 거리로 흉내 내는 것이지 붙음 자체를 보는 것이 아니다. 스크롤 이벤트 대신 `IntersectionObserver`에 `rootMargin: -1px 0 0 0`, `threshold: 1`을 건다 — `top: 0`에 붙는 순간 윗줄 1px이 관찰 영역 밖으로 나간다.

ADR-0015의 세 조건을 지킨다. ① 스크립트가 없으면 선이 안 보일 뿐이고 붙는 것은 CSS가 한다 — 동작 없는 표시가 생기지 않는다. ② 마크업을 건드리지 않는다. ③ `js()` 헬퍼로 불러 `?v=`를 받는다.

**폭 예산은 하한을 낮춰 맞춘다.** island은 열 바깥에 있어 뷰포트 전체를 썼지만, 이제 열 안이라 320px에서 280px밖에 없다. 분기점 없이 세 값의 하한만 낮췄다 — 링크 사이 4→0px, 자간 0.06→0.02em, 링크 좌우 패딩 5→3px. 전부 480px 언저리에서 원래 값으로 돌아온다. 링크 사이가 0이어도 클릭 영역이 맞닿을 뿐 글자 사이는 패딩이 벌린다.

| 뷰포트 | 브랜드 왼쪽 / 열 왼쪽 | 마지막 글자 오른쪽 / 열 오른쪽 |
|---|---|---|
| 320px | 20 / 20 | 300 / 300 |
| 360px | 20 / 20 | 340 / 340 |
| 768px | 140 / 140 | 628 / 628 |
| 1400px | 373 / 373 | 1027 / 1027 |

(오버레이 스크롤바 기준. 320px에서 여유는 0px이다. 상시 스크롤바를 쓰는 데스크탑 브라우저를 320px로 좁히면 좌우 20px 여백 안으로 6px 들어가지만 가로 스크롤은 생기지 않는다.)

**햄버거는 다시 들이지 않았다.** 이번에 선택지로 다시 열었지만, 링크 셋이 320px 열에 들어가는 한 접을 이유가 없다는 ADR-0009의 판단은 형태와 무관하게 유효하다.

## 결과

- `--island-*` 변수 셋이 `--nav-gap`, `--nav-link-pad`, `--nav-pad`, `--nav-top`으로 바뀌었다. 여전히 `.mainnav` 안에만 산다.
- 자체 스크립트가 둘이 됐다(`lightbox.js`, `nav.js`).
- `/projects`처럼 열(`.container`)이 없는 화면도 같은 규칙으로 그려진다 — 요소가 열 바깥에서 `--column`을 직접 쓰기 때문이다.
- 링크가 넷 이상으로 늘면 320px의 여유가 먼저 사라진다. 그때도 분기가 아니라 유동값의 하한을 낮추는 쪽으로 푼다. 더 내릴 곳이 없으면 그때 접기를 다시 논한다.
- `CONTEXT.md`의 **내비게이션** 정의에서 모양에 관한 문장을 뺐다. 모양은 이 문서가 맡는다.
- 헤딩 앵커로 점프하는 링크가 생기면 sticky 내비게이션이 대상을 가린다. 그때 `scroll-padding-top`을 더한다.
