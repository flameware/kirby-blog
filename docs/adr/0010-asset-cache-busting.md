# ADR-0010: 스타일시트 URL은 파일 수정시각을 달고 나간다

- **상태:** 채택
- **날짜:** 2026-08-18
- **관련:** [ADR-0008](0008-type-scale.md)

## 맥락

[ADR-0008](0008-type-scale.md)로 타입 스케일을 바꿔 배포한 뒤, iOS Safari에서 홈 인사말만 옛날 크기로 나오는 화면이 보고됐다. 처음에는 모바일 Safari의 폰트 버그로 의심했지만 아니었다.

증거는 두 가지였다. 같은 화면인데 **내비게이션·블로그 목록·작성일은 크기가 같았고 인사말 문단만 달랐다.** 폰트 부풀리기나 페이지 확대라면 전부 같이 커졌어야 한다. 그리고 낡은 쪽에서는 인사말의 `<br />`이 살아서 4줄로 끊겼다 — `.home-intro br { display: none }`은 ADR-0008에서 새로 들어간 규칙이다.

즉 **그 탭이 예전 `home.css`를 쓰고 있었다.** 서버의 파일은 새것이었고, 새 탭으로 열면 정상이었다.

캐시가 이렇게 오래 남는 조건이 두 겹이었다.

1. **URL이 내용과 무관하다.** `css()`가 뽑는 주소에는 버전이 없어서, 파일이 바뀌어도 브라우저에게는 같은 자원이다.
2. **서버가 `Cache-Control`을 주지 않는다.** 브라우저는 휴리스틱(보통 `Last-Modified` 기준 나이의 10%)으로 신선도를 스스로 정한다. 게다가 iOS Safari는 열려 있던 탭을 복원할 때 네트워크에 아무것도 묻지 않아서, 사용자가 새로고침하기 전까지는 만료 여부조차 따지지 않는다.

이건 한 번의 사고가 아니라 **CSS를 고칠 때마다 반복될 조건**이다. 배포하고 폰으로 확인했는데 안 바뀐 것처럼 보이면, 다음번엔 있지도 않은 CSS 버그를 쫓게 된다.

## 결정

**스타일시트 URL에 그 파일의 `filemtime`을 쿼리로 붙인다.** 내용이 바뀌면 주소가 바뀌므로, 캐시 정책과 무관하게 다음 요청에서 새 파일을 받는다.

붙이는 자리는 Kirby의 **`css` 컴포넌트**다. `css()` 헬퍼가 URL을 뱉기 직전에 거치는 지점이라, 템플릿을 하나도 고치지 않고 `header.php`의 `css("@auto")`까지 함께 처리된다 — 헬퍼가 `@auto`를 실제 경로로 바꾼 **다음에** 컴포넌트를 부르기 때문이다.

```php
App::plugin("massivevoid/assets", [
    "components" => [
        "css" => fn(App $kirby, string $url, $options = null): string
            => assetVersionedUrl($kirby, $url),
    ],
]);
```

이 서버에 실물이 없는 주소(외부 CDN 등)와 이미 쿼리가 붙은 주소는 손대지 않고 그대로 돌려준다.

**곁들여 `-webkit-text-size-adjust: 100%`를 `index.css`에 직접 넣었다.** iOS Safari의 자동 텍스트 크기 조정(font boosting)은 이번 원인이 아니지만, 켜지면 좁은 화면에서 본문 블록만 제멋대로 부풀어 ADR-0008이 정한 유동 단위를 무력화하는 **실재하는** 기능이다. 지금은 CDN의 normalize.css가 막아주고 있었는데, 타입 스케일이 남의 서버가 살아 있는지에 기대고 있을 이유가 없다.

## 근거

**컴포넌트가 자리로 옳다.** `header.php`에서 URL을 손으로 조립하는 방법도 있었지만, 그러면 `@auto`를 풀어헤쳐 템플릿 이름으로 경로를 다시 만들어야 한다 — Kirby가 이미 하는 일을 템플릿에 복사하는 것이다. 컴포넌트는 한 곳이고, 나중에 `js()`가 생겨도 같은 자리에 붙는다.

**`config.php`가 아니라 플러그인인 것은 선택이 아니다.** Kirby는 설정 파일에서 `api`·`routes`·`hooks` 셋만 확장으로 읽는다(`AppPlugins::extensionsFromOptions()`). `components`를 `config.php`에 써도 **조용히 무시된다** — 실제로 그렇게 먼저 짰다가 URL에 버전이 안 붙는 것을 보고 알았다. 직접 만든 플러그인이므로 `.gitignore`의 `!/site/plugins/assets` 예외를 같은 커밋에 넣었다(CLAUDE.md가 경고하는 함정).

**해시가 아니라 수정시각인 것은 빌드 단계가 없어서다.** 이 사이트의 CSS는 손으로 쓰고 그대로 서빙한다. 파일 내용을 읽어 해시를 뜨는 것이 더 정확하지만(수정시각만 바뀌고 내용이 같은 경우), 매 요청마다 파일을 읽게 된다. `filemtime`은 `stat` 한 번이고, 배포가 곧 파일 교체인 이 구조에서는 같은 답을 준다.

**쿼리 문자열을 택했다.** 파일명에 해시를 박는 방식(`index.a1b2c3.css`)이 프록시 캐시에 더 안전하다고 알려져 있지만, 그건 빌드 산출물 이야기다. 여기서는 파일 이름이 곧 저장소의 파일 이름이고, 그걸 바꾸려면 없던 빌드 단계가 필요하다.

## 결과

- 배포 직후 발행되는 URL이 `…/assets/css/index.css?v=1787012704` 꼴이 된다. 홈·블로그·404(템플릿 CSS 없음)에서 확인했다.
- **다음 CSS 변경이 즉시 반영된다.** 폰에서 안 바뀐 것처럼 보이면 그건 이제 진짜 다른 문제라는 뜻이다.
- **아직 남은 것: 서버가 `Cache-Control`을 주지 않는다.** URL이 내용을 따라가게 됐으니 이제 `max-age`를 길게 주는 것이 안전해졌다 — 오히려 지금이 그걸 켤 조건이 갖춰진 시점이다. Apache 설정이라 이 저장소 바깥의 일이고, 배포 문서가 공개 대상이 아니라(`.gitignore`의 Security 절) 여기에는 결정만 적어둔다.
- 컴포넌트는 `css()`만 감쌌다. `js()`는 이 사이트에 스크립트 파일이 없어서 두지 않았다 — 생기면 같은 자리에 한 줄 더한다.
